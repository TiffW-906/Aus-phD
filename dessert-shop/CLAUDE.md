# Wu.D dessert 線上訂購網站 — 專案說明

## 目標
讓客人在網站上挑選甜點、加入購物車、選擇取貨時間並付款；
賣家有一個後台可以查看、核對、整理所有訂單（類似表單後台），
並隨時更新商品現貨狀態與公休日。

## 範圍
- **只做工作室自取**，不做任何寄送（不做 7-11 店到店、黑貓宅配、運費計算、收件地址）。
- 工作室取貨地址：**宜蘭市延平路39巷13號**
- 結帳頁與完成頁要顯示取貨地址與營業時段，並附 Google 地圖連結（用地址組成查詢網址即可，不需要 API 金鑰）。
- 頁面放一行提示：需要寄送或訂購整模蛋糕／餐盒／禮盒，請洽 LINE @327uqhcn。

## 技術組合
- Next.js（App Router, TypeScript）
- Supabase（PostgreSQL 資料庫 + 管理員登入）
- LINE Pay Online API v3（先用 Sandbox 測試環境）
- 部署：Vercel
- 樣式：Tailwind CSS
- 時區一律使用 Asia/Taipei

## 取貨規則
- 營業取貨日：每週一到週四，12:00–19:00（後台可修改）。
- 取貨時段：每 30 分鐘一格（12:00、12:30 … 18:30）。
- 公休日：由賣家在後台隨時新增或刪除特定日期，這些日期不能被選為取貨日。
- 每件商品依「商品狀態」決定最早可取貨日：
  - **現貨**：最快當天取貨。當天只能選「現在時間 + 1 小時」之後的時段。
  - **可預訂**：最快在「今天 + 該商品的預訂天數」之後取貨。
  - 所有商品（含接單製作 🚚）沒有現貨時，預訂天數一律預設 3 天，
    後台可逐項修改（範圍 3–5 天，例如較費工的品項改成 5 天）。
- 一張訂單只會有一個取貨時間。購物車內有多種商品時，
  **最早可取貨日 = 所有商品中最晚的那一個**，結帳頁要清楚說明原因
  （例如：「購物車內有接單製作的餅乾，最快 10/23 可取貨」）。
- 日期選擇器只能選：營業取貨日、非公休日、且不早於最早可取貨日；最遠可預訂 30 天。

## 商品狀態（後台可隨時切換）
每個商品有 `stock_status`：
- `in_stock` 現貨：前台顯示「今日現貨」標籤，可設定剩餘數量（選填）。
- `preorder` 可預訂：前台顯示「需預訂 N 天」標籤。
- `unavailable` 暫停供應：前台不顯示。

規則：
- 現貨若有設定數量，下單成功時扣除數量；訂單取消時補回；
  扣庫存必須用資料庫交易（transaction）避免超賣。
- 數量歸零時，前台顯示「今日已售完」，並依商品設定自動轉為 `preorder` 或 `unavailable`。
- 首頁最上方有「今日現貨」區塊，集中顯示所有現貨商品；下方再依分類列出全部商品。

## 頁面
### 前台（客人）
1. **商品頁 `/`**：「今日現貨」區塊 + 依分類分區（主要商品／麵包／罐裝冷飲／常溫餅乾）。
   每張商品卡：圖片、名稱、價格、狀態標籤（今日現貨／需預訂 N 天）、溫層標籤、「加入購物車」。
   有口味的商品，加入前要先選口味。
2. **購物車**：右下角浮動按鈕顯示件數，點開為側邊抽屜；可增減數量、刪除、看小計、看最早可取貨日。
3. **結帳頁 `/checkout`**：姓名、手機、LINE 名稱（選填）、取貨日期與時段、備註；
   付款方式只有兩種：
   - LINE Pay（線上付款）
   - 現場自取付現金
4. **訂單完成頁 `/order/[orderNo]`**：訂單編號、明細、付款狀態、取貨日期時段與地址。

### 後台（賣家，需登入，**手機操作優先**）
1. **今日總覽 `/admin`**：今天要取貨的訂單、今天的現貨狀態一覽。
   - **新訂單即時出現**：使用 Supabase Realtime 監聽 orders 表，客人一下單，
     後台不用重新整理就會自動出現在最上方，並標示「新」。
   - 新訂單進來時跳出提示並播放提示音（可在後台開關聲音）。
   - 後台頁面的分頁標題顯示未讀新訂單數，例如「(3) Wu.D 後台」。
   - 賣家點開或按「已讀」後，「新」標示消失。
2. **商品狀態 `/admin/products`**：每個商品一列，可以一鍵切換 現貨／可預訂／暫停，
   直接修改剩餘數量與預訂天數。這頁要做到賣家每天早上用手機一兩分鐘就能更新完。
   每個商品可以直接從手機上傳或更換照片（存到 Supabase Storage，上傳時自動壓縮並裁成正方形）。
3. **訂單列表 `/admin/orders`**：直接在後台瀏覽所有訂單，同樣即時更新。
   手機上以卡片呈現、電腦上以表格呈現，可依取貨日期、付款方式、狀態篩選與搜尋。
   CSV 匯出只是選用的備份功能，日常查看與核對都在後台完成。
4. **訂單詳細**：查看明細、修改訂單狀態、標記現金已收款。
5. **營業設定 `/admin/settings`**：
   - 公休日月曆：點選日期即可設為公休／取消公休，可填原因。
   - 營業取貨日（星期幾）、取貨開始與結束時間。
   - 若某公休日已經有訂單，設定時要跳出警告並列出受影響的訂單。

## 資料表
- `products`：id, name, category, price, unit_note, temp_type, flavors (text[]), image_url,
  stock_status (`in_stock` | `preorder` | `unavailable`), stock_qty (int, 可為 null 代表不限量),
  lead_days (int，預設 3，後台可改 3–5), sold_out_fallback (`preorder` | `unavailable`), sort_order
- `orders`：id, order_no, customer_name, phone, line_name, pickup_date, pickup_time,
  payment_method (`linepay` | `cash`), payment_status (`unpaid` | `paid` | `refunded`),
  order_status (`pending` | `confirmed` | `ready` | `completed` | `cancelled`),
  total_amount, note, linepay_transaction_id, is_read (bool，預設 false), created_at
- `order_items`：id, order_id, product_id, product_name（快照）, flavor, unit_price（快照）,
  quantity, subtotal, was_in_stock (bool，下單當下是否為現貨)
- `store_settings`（單列）：open_weekdays (int[]，預設 [1,2,3,4]), open_time (預設 12:00),
  close_time (預設 19:00), slot_minutes (預設 30), same_day_buffer_minutes (預設 60), max_days_ahead (預設 30)
- `closed_dates`：date, reason

`temp_type` 對應菜單圖示：
- `frozen` ❄ 冷凍商品
- `fresh` ☀ 當日出爐為常溫，否則冷凍供應
- `made_to_order` 🚚 接單製作
- `none` 無標示

## 重要規則（不可違反）
- **金額一律在伺服器端用資料庫價格重算**，絕不信任前端傳來的價格或總額。
- **取貨日期與時段也要在伺服器端重新驗證**（營業日、公休日、最早可取貨日、商品狀態、庫存）。
- 訂單明細要存商品名稱與單價的「快照」，之後改價不影響舊訂單。
- LINE Pay 流程：Request API → 導向付款頁 → confirmUrl 呼叫 Confirm API，
  確認金額與訂單相符後才把 payment_status 改為 `paid`。
  LINE Pay 付款失敗或逾時未付款的訂單要釋放已扣除的現貨數量。
- LINE Pay 金鑰只放在伺服器端環境變數，不可出現在前端。
- 後台所有頁面與 API 都要驗證管理員身分（Supabase RLS + 登入）。
- 選擇現金付款時，訂單狀態為 `pending` / `unpaid`，由賣家在後台手動標記收款。

## 視覺風格
- 參考菜單：主色磚紅（約 #B23A48）、淡粉（約 #EBCBCB）、米白底（約 #F7F2EC）
- 圓潤、溫暖、手作感；中文字體可用 Noto Sans TC
- 手機優先設計（客人多從 IG 連結進入）
- 實際色碼與 Logo 待店家提供後更新
- 商品照片尚未提供：先用品牌色的佔位圖（顯示商品名稱），
  所有圖片位置都要能在之後直接替換，不能寫死在版面裡

## 開發順序
1. 商品頁 + 購物車 + 商品狀態標籤（讀 `products.json` 假資料）
2. 建立 Supabase 資料表，把商品資料匯入
3. 後台登入 + 商品狀態頁（現貨／預訂／暫停切換）
4. 營業設定 + 公休日月曆
5. 結帳頁（取貨日期規則 + 現金付款）+ 訂單寫入 + 庫存扣除
6. 訂單完成頁 + 後台訂單列表、狀態修改、CSV 匯出
7. 串接 LINE Pay Sandbox
8. 上線前檢查（正式金鑰、錯誤處理、手機版實測）
